# 安全特性支持矩阵

| 项目 | 内容 |
|---|---|
| 适用 SoC | SpacemiT K3 |
| 适用方案 | Buildroot（安全镜像） |
| 对应 TEE 版本 | `k3-v1.0`（与 OP-TEE 构建配置一致） |
| 矩阵版本 | k3-v1.0（2026-10-12） |

本矩阵中的状态判定与「最低软件版本」列均以上述版本为准。低于标注版本时不具备该特性；版本升级后需按备注中的前提重新确认。

本矩阵面向安全系统 k3-v1.0，不覆盖产测形态；状态取值见下方图例，尚未定论的事项一律按「暂不支持」处理。后续版本迭代时同步更新。

## 概述

### 编写目的

本表汇总 SpacemiT K3 平台在 Buildroot 方案下的安全特性支持情况，按「特性 × SoC 型号 × 软件版本」给出状态与最低版本要求，供方案选型、需求评审与量产评估使用。

### 适用范围

本文档适用于 SpacemiT K3 系列 SoC 的 Buildroot 方案。安全启动的信任链细节参见[安全启动开发指南](../device/secureboot.md)，TEE 的结构与集成参见 [TEE 架构与集成指南](tee_architecture.md)。

> [!IMPORTANT]
> **启动介质容量要求**
>
> 当前安全镜像对启动介质的要求：
>
> - **容量**：要求**大于等于 8M**。4M SPI-NOR 放不下——安全版 `u-boot.itb`（约 2383K）超出其分区余量（1536K）；8M 及以上均可，存在 8M 的 SPI-NOR。
> - **可用介质**：SPI-NOR 8M 及以上、SPI-NAND，或 eMMC / SD / UFS。
> - **详见**：本文「存储介质差异」与 [TEE 镜像构建与烧录说明](tee_image.md)。

### 状态图例

| 标记 | 含义 |
|---|---|
| ✓ 支持 | 已实现并通过实测或构建验证，可直接用于产品 |
| ✗ 不支持 | 当前未实现，或已实现但默认未使能且无明确启用路径 |
| 部分支持 | 可用但受条件限制，需按备注中的前提使用 |
| 未使能 | 代码已就绪，但当前构建未开启该能力；可用配置项开启（需重新构建） |
| 规划中 | 已列入计划但当前不可用 |

「最低软件版本」指出该特性首次可用的软件基线。低于该版本时不具备该特性，升级后需按备注中的前提重新确认。

> [!NOTE]
> 当前仅有一个 SoC 型号（K3）与一个软件基线，因此矩阵暂为单列。后续新增 SoC 或版本时按同一格式扩展列，无需改动结构。

## 安全特性 × SoC × 软件版本

### 信任根与安全启动

| 特性 | 最低软件版本 | K3（当前基线） | 备注 |
|---|---|---|---|
| 信任根（RoT） | `k3-v1.0` | ✓ | 芯片内只读、不可篡改的 BootROM 与 eFuse 密钥材料（RoT 公钥哈希在 bank4）；规范中 hart 固件类信任根，见白皮书 §5 |
| Secure Boot（FIT 逐级验签） | `k3-v1.0` | 部分支持 | 需烧入 ROTPKH（eFuse bank4）；BootROM 依 secure boot 位对 FSBL 验签，后续镜像由 SPL 配置开启；未使能时为非签名启动 |
| ROTPKH 存储 | `k3-v1.0` | ✓ | eFuse bank4，256 bit，值为 root 公钥的 SHA256 |
| FSBL 证书链 | `k3-v1.0` | ✓ | `root_key` + `spl_key`，`oem_key` 携带 spl / uboot 公钥 |
| FIT 公钥注入 | `k3-v1.0` | ✓ | SPL DTB 与各板级 U-Boot DTB |
| 防回滚计数器 | `k3-v1.0` | 未使能 | 字段已定义（ARCN-NS / ARCN-Sec），当前未启用、未参与校验 |
| 镜像分区替换（可更新性） | `k3-v1.0` | ✓ | 各分区镜像可独立替换；启动前不做度量与验签，见白皮书 §12 |
| TEE 镜像签名 | `k3-v1.0` | 部分支持 | 默认 FIT 描述仅含 crc32、无 RSA 验签；支持传入 `KEY_DIR` 打包签名版 FIT，当前构建流程不传该变量 |

### 密钥体系与 eFuse

| 特性 | 最低软件版本 | K3（当前基线） | 备注 |
|---|---|---|---|
| eFuse 只读访问（安全世界） | `k3-v1.0` | ✓ | CPU 直读 GEU 寄存器块；12 bank × 256 bit |
| eFuse 烧写 | `k3-v1.0` | ✓ | 由专用的 eFuse 烧写工具在产线完成；安全世界按设计不提供写路径 |
| eFuse 读回校验 | `k3-v1.0` | ✓ | 可读 per-bank 锁定位 |
| TE200 访问 eFuse | `k3-v1.0` | ✓ | 安全引擎的密钥阶梯在引擎内自取 eFuse 中的根密钥，CPU 不参与；其余 eFuse 内容的读取仍由 CPU 侧只读驱动完成 |
| HUK 来源与派生 | `k3-v1.0` | ✓ | 根密钥取自 eFuse（SoC 厂烧写），由安全引擎的密钥阶梯在引擎内派生工作密钥与各级子密钥；CPU 不可读，软件全程不接触根密钥 |
| 未烧 fuse 时的启动策略 | `k3-v1.0` | 部分支持 | CM/DM 阶段可启动（DM 要求 chip id 已烧录），此时子密钥不具备设备唯一性；SP 阶段要求 chip id、HUK 与安全启动熔丝齐备 |
| 安全引擎 HUK 自检 | `k3-v1.0` | 未使能 | 开关为 `CFG_TE200_HUK_SELFTEST`，默认关闭；开启时开机打印 CMAC/KDF 与根密钥状态，失败只告警、不拦启动 |
| 子密钥派生 | `k3-v1.0` | ✓ | RPMB / SSK / DIE_ID / UNIQUE_TA / TA_ENC / SE050；由引擎内工作密钥经 CMAC 与 KDF 派生 |
| 存储密钥层级（SSK/TSK/FEK） | `k3-v1.0` | ✓ | 由 HUK 逐级派生 |
| 核心加固（ASLR / 栈保护等） | `k3-v1.0` | 部分支持 | 平台强制关闭地址随机化与栈保护 |

### 安全存储

| 特性 | 最低软件版本 | K3（当前基线） | 备注 |
|---|---|---|---|
| REE FS 存储 | `k3-v1.0` | 部分支持 | 默认后端；**无抗回滚保护** |
| REE FS 完整性 + RPMB | `k3-v1.0` | 未使能 | 依赖 RPMB 文件系统（`CFG_REE_FS_INTEGRITY_RPMB`），当前未使能 |
| RPMB 存储（eMMC） | `k3-v1.0` | 未使能 | 开关为 `CFG_RPMB_FS`，默认未使能；启用前需器件完成 RPMB 密钥灌注 |
| RPMB 存储（UFS） | `k3-v1.0` | 未使能 | 同 eMMC（开关 `CFG_RPMB_FS`）；探测接口已支持 UFS，块数与 CRC 处理与 eMMC 不同 |
| RPMB key 派生 | `k3-v1.0` | ✓ | 由 HUK 结合器件标识派生；eMMC 用其原生 CID 并掩掉可变字段（PRV、CRC），UFS 用哈希后的 device_id |
| RPMB 灌注目标定向 | `k3-v1.0` | 未使能 | 产测版构建时开启（`CFG_RPMB_WRITE_KEY_CID`）；可按器件标识钉住目标器件，避免多器件写错 |
| RPMB 探测能力声明 | `k3-v1.0` | 未使能 | `CFG_RPMB_ANNOUNCE_PROBE_CAP` 默认开启（向内核声明探测能力），但 `CFG_RPMB_FS` 未使能，探测返回空设备列表 |
| tee-supplicant RPMB 模拟 | `k3-v1.0` | 未使能 | 已显式关闭，避免 ioctl 被文件模拟 |

## 存储介质差异

同一特性在不同存储介质上行为不同，单独列表以避免正文混写。

| 维度 | eMMC | UFS | SPI-NOR | NAND |
|---|---|---|---|---|
| 可运行安全镜像 | ✓ | ✓ | ✓（8M 及以上；4M 放不下安全 U-Boot） | ✓（8M 及以上） |
| 安全镜像 TEE 分区 | 4 MB | 同 eMMC | 512 KB | 512 KB |
| RPMB 可用性 | ✓ | ✓ | ✗ | ✗ |
| RPMB key 派生的器件标识处理 | 用原生 CID（16 字节），掩掉可变字段 PRV 与 CRC | 无原生 CID：device_id 经 BLAKE2s 哈希为 16 字节 | — | — |
| RPMB 读块数语义 | 帧内块数字段须为 0 | 由设备从帧内字段取长度 | — | — |
| TEE 镜像缺失时 SPL 行为 | 中止启动 | 保持宽松 | 中止启动 | 中止启动 |
| 已知限制 | — | — | 4M 容量放不下安全版 U-Boot（超出分区余量） | 同 SPI-NOR |
